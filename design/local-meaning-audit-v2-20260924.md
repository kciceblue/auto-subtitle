# Local self-correction: explicit new-commitment check

This is a continuation of the authorized attempt to reach a confirmed v5 seven,
using existing local models and cached evidence. No download is planned. The
original LC and the human reference remain frozen, as do the rubric and common
external review source/context. The reference and external corrective wording
remain outside local model inputs.

## Why a second mechanism is necessary

Version one found every deliberately wrong control and preserved every correct
control. Its correction of a possessive relationship nevertheless introduced a
gender commitment absent from the Japanese. The first source-only and target-only
frames represented actions and participants without exposing that implicit
attribute, and the fresh verifier accepted it. The strict zero-new-errors gate
failed. We will not waive it or hand-edit that one control.

Version two adds two focused steps to the unchanged discovery and repair logic:

1. Read the complete proposed Chinese window without Japanese, diagnostics,
   reference or prior target. Extract its actual assertions and presuppositions,
   including attributes, relations, quantities, time, modality and participants.
   Each commitment must have a literal Chinese witness. This is a fallible
   interpretation, not a fact ledger certified as true.
2. Compare those commitments with the original Chinese and raw Japanese/evidence.
   Distinguish inherited content from new commitments. Explicitly decide whether
   each new commitment is supported, unsupported or uncertain. Unsupported or
   unresolved new commitments reject the window's proposed edits. Pre-existing
   ambiguity alone does not count as a new regression. The original independent
   verification still runs for proposals that pass this additional check.

No mechanical pronoun replacement, fixed character gender, reference wording or
production error location is supplied. Rejections restore the original text;
this version adds no repeated repair loop. After a rollback, changed neighboring
windows receive fresh checks; identical contexts reuse their saved judgments.

## Reuse and capability gates

All 32 original controls now form development data. Exact matching source,
target, comparison, repair and verification requests reuse their existing native
receipts and backend identities. The 144 completed native generations are not
rerolled. New requests are limited to the new commitment mechanism or a genuinely
changed input context. Every inherited receipt is pinned and replay-validated.

Development gate: at least 14 of the 16 errors actually corrected, no newly
introduced error, and at most one false-positive case. Detection retains all 32
cases in its denominator. Clean controls must remain semantically correct.

A separate author, without receiving the failed example or model outputs,
prepares 20 fresh controls: ten wrong and ten correct, with disjoint names and
content. Expected labels remain outside model requests. A separate reviewer
checks the original labels before execution. The full unchanged version-two
procedure then runs once on these new cases. Required: at least eight of ten
errors detected and corrected, at most one false-positive case, and zero new
errors. Missing, invalid or unresolved cases do not count as correct repairs.
Any tuning after this run consumes this validation set as development data.

These are authored capability controls, not a real-world accuracy estimate.
Independent semantic audits bind to exact inputs, outputs and native request
provenance. Current producer pins and thresholds must match before production.

## Episode and review

If both gates pass, every one of the 67 frozen episode owners receives the same
discovery procedure with three-owner focus and two neighbors on either side,
using the full cached union of 933 observations. Start from the original LC.
This changes both the checking procedure and the evidence available relative to
LC alone; a successful score would not isolate which component caused the gain.

Apply the same exact-text subtitle formatter, then freeze two independent v5
reviews against byte-identical common source/context. No score-conditioned reroll
or unchanged-candidate rescore is allowed. Seven in both reviews is the target;
the result remains a text review, not audio/playback or release certification.
